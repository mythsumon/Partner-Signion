# Partner-Signion

SIGNION 파트너 관리자 (KT 외국인 휴대폰 개통) 화면 프로토타입 v0.3

- `index.html` — 단일 파일 프로토타입 (서버 불필요, 브라우저로 바로 열림)
- `assets/` — SIGNION 로고 원본 SVG (BI 가이드라인 기준)
- `DEVELOPERS.md` — 개발자가 꼭 지켜야 할 업무 규칙 (မြန်မာ) · 한국어판 `DEVELOPERS.ko.md`
- `backoffice/` — 내부 관리자(SIGNION BackOffice) 프로토타입. 대리점별 계약 · 요금 설정, 사용량, 확장팩 이력, 월 정산 · 마감, 공통 서버 집계 화면 포함 (`backoffice/README.md`, 개발 명세 `backoffice/DEVELOPERS.md`)

근거: 「SIGNION 파트너 관리자 기획서 v0.1」 (화면 A1~F2, 관리자 위계 4단계) · 「KT 통합 Admin 정책 — 대리점별 이용량·과금 관리」의 **고객사 어드민** 범위 · 「SIGNION KT 통합관리자시스템 기능 구성_1026.xlsx」(기능 구성 · 과금체계 시트) · 디자인: SIGNION BI 가이드 (BackOffice와 공용 디자인 시스템)

- 로그인: 하단 「데모 계정」 버튼(헤드마스터 · 마스터 · 총괄 · 서브)을 누른 뒤 다음 → 인증. 오른쪽 위에서 한국어 / English 전환(선택 기억). 「최초 로그인으로 체험」을 체크하면 최초 로그인 3단계 인증을 볼 수 있습니다.
- 상단 「보기 권한」으로 위계별 메뉴·조회 범위를 바꿔 볼 수 있습니다 (프로토타입 전용)
- 「이용 현황」 하단의 「한도 시나리오」로 용량 경고 · 초과 차단 · 처리 한도 도달 · 확장팩 해제 흐름을 확인할 수 있습니다 (프로토타입 전용)
- 모든 이름·번호·건수·금액은 예시 데이터입니다.

| 인증결과 상세 | 「MRZ 이중 확인」 줄을 없애고 인증 결과 카드 아래 **인증 상세 내역** 아코디언(기본 접힘, 누르면 펼치기 · 다시 누르면 접기). 순번 · 인증코드 · 인증단계명 · 진행결과(진행요청 · 성공 · 실패 · 중단) · 처리일시 · 비고 — 요청 → AI OCR → 여권 NFC → 안면 · 라이브니스 → KYC 인증 완료. 실패 · 중단 건은 해당 단계에서 멈추고 비고에 사유(오류코드). 단계 코드 · 이름은 예시 — SIGNION 연동규격 기준으로 맞출 것 |
| 대시보드 | ① **처리 단계별 현황** 맨 위 — 인증 성공 누적 · 진행 중 · 개통 완료 · 완료율, 단계별 건수 · 비율(누르면 인증결과 그 단계) ② **개통 완료 & 인증 추이** — 기간 인증 성공 · 개통 완료 건수 박스 2개 + 일별 묶음 막대(개통은 다음 날 처리 반영) ③ **고객 구성 현황** — 성별 · 연령대 · 비자 + 알림(성별 · 연령은 예시 비율) ④ **하위 조직별 현황** — 처리 · 성공 · 실패 · 성공률 · 개통 완료 · 개통률 · 검수 대기 · 합계. 실패 사유 가로 막대 · 상단 KPI 4개 삭제 |
| 관리자 계정 구조 | 마스터 계정은 SIGNION 백오피스에서 파트너 등록 시 발급. 마스터 → 총괄 관리자 · 소속 직원 / 총괄 → 서브 관리자 · 소속 직원 / 서브 → 소속 영업 직원 / 직원 → 등록 권한 없음. KT 헤드마스터는 조회 전용 |
| 계정 관리 메뉴 | 서브에게도 「계정 관리」 — 등록 버튼은 위계와 관계없이 「계정 등록」. 각 관리자는 하위 관리자와 본인 조직 직원을 등록 · 수정 · 중지 · 삭제. 화면 위에 등록 권한 안내 |
| 계정 등록 | 「계정 등록」 모달 하나로 — 계정 유형 카드 4종(마스터 · 총괄 · 서브 관리자 · 직원 계정, 내가 등록할 수 없는 유형은 흐리게 + 누가 등록하는지 표시) · 소속 · 관리 범위 안내 · 아이디 · 초기 비밀번호(복사 버튼) · 메뉴별 권한. 직원은 등록한 관리자의 조직에 자동 연결. 새 계정은 「최초 인증 대기」로 표시, 발급자 기록 |
| 조직 등록 | 계정 관리 › 조직 카드 「조직 등록」, 계정 등록 창 소속 드롭다운 맨 아래 「+ 새 총괄/영업 사무소 등록」. 마스터: 총괄 사무소(국가 선택) · 영업 사무소 / 총괄: 소속 영업 사무소 / 서브 · KT: 없음. 조직 코드 자동(수정 가능) · 중복 확인. 등록 후 그 조직 관리자 계정 등록으로 바로 이어짐(계정 등록 창에서 왔으면 입력 유지 · 새 조직 자동 선택). 새 영업소는 여권인증 · 인증결과에 바로 나옴. 「조직 등록」 로그 |
| 메뉴별 권한 | 계정마다 메뉴별 조회(View) · 등록(Create) · 수정(Edit) · 삭제(Delete) · 다운로드(Export) 체크. 메뉴에 없는 동작은 「—」. 발급 관리자 자기 권한 안에서만 부여, 대시보드 조회는 항상 허용. 「기본값 · 조회만 · 전체」 빠른 선택. 조회를 빼면 그 메뉴는 GNB에서 숨고 주소로 들어와도 차단, 다른 권한이 없으면 버튼을 눌러도 「권한이 없습니다」. 계정 수정에서도 변경 가능, 「권한 변경」 로그 |
| 최초 로그인 (1회) | ① 아이디 · 비밀번호 → 계정을 발급한 관리자의 메일로 인증번호 → 발급 관리자에게 받아 입력 ② 본인 메일 등록 ③ 본인 메일 재인증 → 이용 시작. 직원 계정도 동일. 감사 로그 「최초 로그인 인증」 |
| 메일 변경 | 사용자 메뉴 「내 메일 변경」 — 새 메일로 받은 인증번호 확인해야 변경. 관리자가 하위 계정 메일을 바꾸면 「메일 재인증 대기」 |
| 직원 계정 과금 | 기본 제공 · 유료 추가 계정 수에 넣지 않음 (「직원 계정」 표시) — **KT 확인 필요** |

## 확인이 필요한 정책 (프로토타입에서 임의로 정한 부분)

- **확장팩 적용 기간** — 신청 월에만 한도에 더한다고 가정했습니다(다음 달은 다시 신청). 계속 유지되는지 확인 필요.
- **유료 추가 계정 판정** — 총괄은 대리점 전체 총괄 수, 서브는 같은 총괄 사무소의 서브 수가 기본 제공 수(3) 이상이면 유료로 정했습니다. 기본 계정을 지운 뒤 기존 유료 계정이 기본으로 바뀌는지는 정하지 않았습니다.
- **계정 등록 범위** — 11월 계정 정책대로 마스터는 총괄 · 소속 직원만 직접 등록합니다(서브는 총괄이 등록, 마스터는 서브 수정 · 중지 · 삭제만 가능). 직원의 메뉴 · 권한(여권인증 · 인증 결과 등)은 KT가 따로 정리해 주기로 해, 직원으로 로그인한 화면은 아직 없습니다.
- **외부 전송량 초과** — 확장팩 산정에만 넣고 업로드 · 다운로드 차단은 하지 않았습니다. 차단 여부 확인 필요.
- **모듈별 이용량** — 인증 1건 = OCR + 안면인식 호출로 보고, 건당 단가는 인증 1건 기준으로 계산했습니다.
- **계약 · 요금 / 월 이용료 노출 범위** — 마스터와 KT 헤드마스터만 보게 했습니다. 총괄 · 서브는 「이용 현황」만 봅니다.
